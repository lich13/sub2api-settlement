# 结算规则

- 原始消费 `usage_logs.total_cost` 决定占比；人民币真实成本按整数分保存，界面金额统一两位小数。原价计算不提前舍入，尾差采用最大余数法、用户 ID 升序打破并列。
- 新增、修改、升级付费和续费只使用准确成本；旧客户端显式提交 `cost_kind=estimated` 会被拒绝。未结算成本可修改，旧预览随版本变化失效；结算后冻结快照。自己的份额自行承担，独立账号零消费由垫付人承担。
- 周期为北京时间输入的 `[start,end)`。同账号不重叠；影子账号归并母账号。免费资源不出单。
- 周期起点支持精确时间、按时间估算和从最早已采集使用开始。时间估算精确到北京时间分钟，从所选分钟 00 秒起计入消费，预览中确认起点后才能出单。旧日期估算及旧接口继续按当天 00:00 至次日 00:00 处理；最早使用起点记录来源用量 ID。
- 管理员的“全部账号”包含当前付费、免费和待配置账号，也可分别筛选；没有消费或尚未配置的母账号仍可管理。普通用户仅能查看已配置付费账号。
- 免费账号可在行内“升级付费”，保存时开始计费，升级前用量不计入，历史账目保留。
- 当前账号名称与开放周期名称跟随主站，账号核对每 5 秒更新名称与可见范围；不再单独编辑公开名称。新出单冻结当时的主站名称，之后改名不会改写已出单名称。
- 已删除的历史账号从运营筛选、账号成本和周期列表隐藏，底层历史账目与用量记录保留。账号状态独立轻量核对，页面可见时每 5 秒刷新，不等待整批消费同步；核对失败保留最近状态并提示。
- 账号成本页可单独结算或结算并续费；续费周期从上一周期结束时间连续开始，成本、垫付人与账单独立计算。
- 可勾选“出单后删除账号”，与续期互斥。出单成功后调用官方删除接口，包含关联影子账号；删除失败不撤销账单，可在管理视图单独重试或取消任务。结果不确定或重启后先核验源状态，避免重复操作。
- 同两人之间的全部待付款订单自动对冲，包含跨账号、周期、固定费用和已有合并单；每张原单只计一次，不进行多人债务转移。净付款人确认转账后双方原单一次结清，零净额由任一当事人确认对冲。收款页只读显示净应收。历史待处理订单仍由管理员单独处理。
- 打开结算弹窗即自动核算，修改截止时间、确认起点或账单后自动刷新；预览过期重新核算，截止时间保持不变。正式出单仍需点击“确认结算”。
- 周期明细和结算预览显示“本次计费人民币金额 ÷ 周期原始总消费”的倍率，不进行汇率换算。精准匹配使用已匹配的本次计费金额，未匹配费用不计入分子；分母保持原始精度。倍率显示四位小数，正值不足 `0.0001` 时显示 `<0.0001×`，零消费或消费不可用时显示 `—`。倍率只作展示，不参与分摊、尾差或账务摘要；历史倍率从冻结快照计算。
- 付款确认会重新核对双方完整订单集合；订单新增、作废、合并、拆分或版本变化时须刷新后重新确认。已结清的对冲记录保存双向原额、抵扣金额和实际转账额，原始金额与分摊快照不改写。
- 未报已付的整次结算可作废重算；已报已付或结清的账目锁定。无需外接支付服务，不修改 Sub2API 余额。

- 固定费用按手选参与人均摊或自定义比例分摊，比例最多两位小数且合计 100.00%；均摊按等权计算。与账号费用复用订单、对冲、收款及作废流程。
- 待确认起点可直接填写准确时间，或以充值时间查询母账号及影子账号的首请求；保存原始时间精度、来源记录和确认审计。
- 上游 CSV 使用 `Time`、`Model`、`Billed Cost`、`Input Tokens`、`Output Tokens`、`Cache Read Tokens`、`Cache Creation Tokens` 字段，可选 `Request ID` / `Upstream Request ID`；时间需含时区，金额按人民币处理。总额先按十进制求和再四舍五入到分。
- 所有独立付费开放周期点击“结算”后，弹窗首屏均提供上游账单导入；已导入账单可从同一入口替换。账单确认后留在当前弹窗并自动刷新分摊预览。
- 请求 ID 优先匹配，否则模型、四种 Token 数相同且时间差不超过 5 秒；候选须唯一且一对一。默认“比例分摊”将账单总成本按已匹配上游扣费的比例分摊，未匹配差异需显式确认。
- 手动选择“精准匹配”后，只汇总各用户匹配请求的上游扣费，未匹配费用不计入账单。保留上游总成本，另外展示本次计费与排除金额；按用户汇总后采用最大余数法处理分币尾差。两种模式均要求正金额匹配依据，范围外记录仍需确认排除。
- 账单替换成本并保留历史；同文件不重复计费，修改截止时间后需重新导入或确认沿用账单。正式出单冻结导入摘要、匹配与分摊依据。

## 账号组统一成本

- 从待配置母账号一步创建账号组，同时填写组名称、准确总成本、统一垫付人和共同起点。已配置独立账号、免费账号、已删除账号及影子账号不能新加入；影子消费仍归并母账号。一个母账号同时只属于一个组。
- 每组使用统一的 `[start,end)` 窗口、一笔准确固定总成本 `C`（整数分）和一位垫付人，不要求成员先填写独立成本，也不累加成员成本。当前成员关系与各期冻结范围分别保存。
- 未出单时从组入口修改成本、垫付人和共同起点，当前成员只可追加、不可移出。追加待配置账号沿用共同起点，递增组和账期版本，使整组旧预览与账单确认失效。锁定的免费升级起点及已有账期边界不得绕过。
- 出单前必须导入或重新确认整组上游账单。导入前只展示组总成本，账号份额与个人应付显示“待账单拆分”；未知金额不计为零。独立账号仍按原规则展示预估。
- 组账单在全部母账号及影子账号的窗口内统一匹配。请求 ID 优先，否则模型、四类 Token 和五秒时间窗都须符合；候选唯一且一对一。跨账号歧义不得猜测归属。
- 设账号已匹配上游扣费为 `M_a`，合计为 `M`，窗口内未匹配扣费为 `U`。`M>0` 时，账号的未匹配份额为 `U_a=U×M_a/M`，以 `G_a=M_a+U_a` 分配组成本。若 `M=0`，改按账号本地原始消费 `W_a` 分配；本地权重也全零则禁止确认和出单。账号内按已匹配用户上游扣费分配，未匹配部分沿用相同比例；无匹配时按该账号本地用户原始消费分配。
- 组成本先按账号最大余数法分到分，再在账号内按用户最大余数法分配，分别按账号 ID、用户 ID 升序打破并列。中间比例使用全精度有理数，不逐请求舍入；账号份额合计等于 `C`，用户份额合计等于账号份额。垫付人自己的份额自行承担。
- 账单计入行的原始金额求和得到 `T`，仅展示时四舍五入到分。原始 `T≠C`、存在未匹配记录或覆盖缺口时须显式确认差异，不足一分的非零差异也须提示；范围外行须另行确认排除，不计入 `T`、`M` 或 `U`。账单只提供拆分权重和对账依据，不自动修改 `C`，本版不提供 `adopt_bill_total`。
- 账号组只允许比例分摊，不能丢弃未匹配费用。独立账号继续支持比例分摊和精准匹配；精准匹配明确排除未匹配扣费。两条路径分别保存规则摘要，不修改旧账单摘要。
- 必须整组预览和出单，不能单独使用组总成本。出单同时冻结成员、成本、名称、账单和用量依据；后续成本、归属或名称修改不影响历史。
- 结算后保留组与成员关系，暂不续费时显示“已结算／待续费”。整组续费从上期结束时间连续开始，自动沿用全部存续成员、准确总成本和垫付人；仅可调整下期总成本和垫付人，不选择部分成员。已删除或明确选择出单后删除的成员不进入下期，删除失败仍独立重试；没有可续费成员时必须取消续费。
- 已结算待续费的组可追加待配置账号，新增成员从下期生效，不改变已结算范围。成员不能通过独立配置、新周期或标记免费等入口离组；仅在没有开放账期时可归档整组，明确确认释放的成员后恢复待配置。已删除成员在运营列表隐藏，其本期消费与财务明细仍保留并参加整组结算。
- 作废必须针对整组；任一相关订单已报已付、已结清，或删除任务正在处理，均不得作废。作废保留原窗口和历史快照，不修改已有续费周期。

## 旧成本配置维护

schema 迁移不把旧模糊成本自动改成准确成本，也不自动清理费用配置。旧未确认成本继续阻止出单，管理员可明确修改为准确成本。需要重新配置时，维护命令只撤销指定版本的未出单模糊成本草稿并使其预览失效，保留历史账目、消费、导入记录和操作审计。准确成本、免费标记、固定费用及系统设置不在重置范围内。

## 账号组操作与接口

在“账号成本 → 账号费用 → 新建账号组”选择待配置账号，一次保存首期。组入口提供添加账号、修改组成本、整组结算和续费；成员仅提供明细。普通用户只能读取公开组信息及自己的分摊。结算自动预览，导入或沿用本窗口账单并确认差异后才可正式出单。

以下路由均位于 `/settlement/api/v1`，写操作要求管理员身份、CSRF 和幂等键；修改携带组及账期版本；编辑既有账期和确认起点时携带完整成员 `cycle_id` 与 `version`。后台继续使用 `vendor` 标识。

| 方法与路由 | 用途 |
| --- | --- |
| `GET /vendors` | 公开组成本、垫付人和周期元数据，不返回原始账单或其他用户消费 |
| `POST /vendors` | `account_ids`、`start`、`start_mode` 与组名称、成本、垫付人原子创建组和首期；旧的仅默认设置请求仍兼容 |
| `POST /vendors/{id}/members` | `version`、`period_version`（待续费时为 `null`）、`account_ids` 追加待配置账号 |
| `POST /vendors/{id}/renew` | `version`、上一期 `period_version`、`cost`、`creditor_id` 整组续费 |
| `PATCH /vendors/{id}`、`POST /vendors/{id}/archive` | 保留默认设置接口；归档仅限无开放账期，并释放当前成员 |
| `POST /vendors/{id}/periods`、`PATCH /vendor-periods/{id}` | 兼容旧空组配置首期（仅 `account_ids`）；修改账期不得替换或移出成员 |
| `POST /vendor-periods/{id}/start-confirm` | 确认共同准确起点，校验全部成员版本 |
| `POST /vendor-periods/{id}/bill-previews` | 上传 CSV 或携带本组 `import_id` 重新确认沿用；只支持比例分摊 |
| `POST /vendor-periods/{id}/bill-confirm` | 确认拆分依据；差异和范围外行分别确认 |
| `GET /vendor-periods/{id}/bill-previews/{preview_id}/unmatched.csv` | 下载当前预览的未匹配及范围外行 |
| `POST /vendor-periods/{id}/void` | 整组作废；已有续费周期保持原状 |

继续使用 `/previews` 和 `/settlements` 出单，`ids` 必须包含账号组账期的全部成员。可同时选择多个完整组、独立账号或固定费用。账号组续费使用 `vendor_renewals`（`period_id`、`version`、`cost`、`creditor_id`），不再要求逐个成员 ID；旧请求明确选择部分成员时返回冲突，不静默扩大范围。独立账号继续使用原 `renewals`。组成员不能通过单账号成本、起点、导入或作废接口绕过整组校验。

## 数据覆盖与异常

启动时完整核对，每分钟按 ID 水位线与最近十分钟窗口增量同步，每日按账号与日期指纹对账。分批暂存后在一个事务中发布，失败或重启不暴露半批结果。单账号预览和出单始终复核所选账号及周期，其他历史变更由每日对账检测。按原 ID 去重，记录已删除时保留之前采集的账务依据。允许保存模糊起点；准确起点确认不改变实际数据覆盖范围。核对清理任务的删除数量与已留存记录，未采集或无法证明完整的范围标为缺口；涉及该范围的手动成本周期不能出单，预估不显示假零。采用上游账单时，比例分摊须由管理员确认本地差异；精准匹配只计入已匹配扣费，无需确认分摊未匹配费用。两种模式都保留缺口提示。源同步失败或中断时禁止结算；已出单周期发现消费变化或缺口标为差异，不自动改变金额。Sub2API 在首次接入前已经删除的记录无法恢复，正式回溯需核对原日志覆盖范围。

新部署不预填真实成本或创建欠款。管理员从“账号成本”配置付费或免费资源。


账单匹配预览可导出未匹配及周期范围外的上游记录，包括原始扣费精度与未匹配原因。导出只反映该次预览，过期、周期修改或出单后须重新匹配；只有创建预览的管理员可下载。CSV 会防护公式注入，导出不会修改费用或请求归属。

## 付款补充信息与删除确认

确认转账或对冲时可填写备注（最多 500 字）及转账凭证编号（最多 128 字）。它们作为独立的不可变补充记录保存，供当事人和管理员查看，不改变净额、原始订单或分摊快照。相同操作编号重试必须携带相同内容。

选择出单后删除账号时，先核对弹窗列出的母账号及影子账号并确认。提交结算与执行删除前都会检查已确认的范围；范围变化不会扩大删除，而是要求重新确认。重试删除也展示当前范围。历史客户端未提交范围摘要时沿用旧协议，建议同步升级前端。
